Features · Specs 011–017

The Context Engine

misterspec's own "Second Brain" — a local-first, deterministic retrieval layer that finds and assembles the smallest sufficient project context for a given operation, so a coding agent doesn't have to re-explore the whole repository by hand every time. It never replaces the agent's own judgment about what the returned context means — only what to hand it in the first place.

011 · Wikilink Graph Foundation

What it is: Parsing and structural validation for [[SPEC-014]] / [[SPEC-014|alias]] syntax inside an artifact's own body.

Why it exists: Formal frontmatter fields (depends_on, parent) already capture structural relationships — wikilinks add an explicit, navigable semantic layer for "this is relevant to that" connections a formal field was never meant to carry.

Example — a wikilink inside a Spec's own body:

## Related Knowledge

See [[KNOW-003|Authentication Model]] for the constraints this Spec assumes.

012 · References and Backlinks

What it is: Query an artifact's own outgoing formal + semantic relationships (references), and every artifact that points back to it (backlinks).

Why it exists: Turns 011's own parsed wikilinks, plus the formal fields foundation already tracks, into an actually queryable graph — the exact building block the Collector (015) traverses.

Example:

misterspec internal references SPEC-014
{"ok":true,"references":{"formal":[{"relation":"depends_on","target":"SPEC-011"}],
"semantic":[{"relation":"wikilink","target":"KNOW-003"}]}}

013 · Document Model and Chunking

What it is: A body/section representation (Document/Section/Chunk) with line-range provenance, plus a lightweight token estimator.

Why it exists: Retrieval needs to work on pieces of an artifact (a heading and its own content), not the whole file — and every chunk needs to know exactly where it came from, for both ranking and human review.

Example — one chunk's own provenance:

type Chunk struct {
    ArtifactID string
    Heading    string  // "## Requirements"
    Content    string
    StartLine  int
    EndLine    int
}

014 · Disposable SQLite Index

What it is: A local, fully-rebuildable FTS5 full-text index over documents, chunks, and links — stored at .misterspec/cache/context.db, never authoritative, never committed.

Why it exists: Fast lookup and free-text search need some index, but Constitution Principle III forbids any secondary authoritative state — deleting this file at any time must cost nothing but a re-sync.

Example — deleting the cache costs nothing:

rm -rf .misterspec/cache
misterspec internal context SPEC-014   # transparently rebuilds, same result

015 · Context Collector and Retrieval

What it is: Collect — gathers a deduplicated, tier-labeled candidate set: mandatory content (Constitution + target), formal structural relationships, direct wikilinks/backlinks, free-text matches, and one bounded second-hop graph expansion.

Why it exists: This is where 011-014 actually come together into one answer to "what's relevant to this target?" — explicit project structure is always consulted before probabilistic text similarity, never the reverse.

Example — one candidate's own tier and reason:

{"path":"ai/.../SPEC-011/spec.md","tier":"structural","reasons":["depends_on"]}

016 · Ranking and Budgeting

What it is: Rank assigns every candidate a deterministic score used only to order candidates already sharing the same Tier — Tier always dominates Score, an absolute, never-crossed invariant. ApplyBudget then fits the ranked list into a token budget, tier by tier, always preserving mandatory content in full.

Why it exists: A strong but coincidental textual match must never outrank a real dependency, no matter how well it happens to match the request's own words — and a budget has to actually mean something, not just sort everything by score and cut wherever the numbers run out.

Example — a well-fitting budget, nothing trimmed:

{"budget":6000,"budget_exceeded":false,"diagnostics":{"reduction_percent":0}}

017 · Internal Context Command

What it is: misterspec internal context — the one CLI entry point orchestrating 014's index readiness, 015's collection, and 016's ranking/budgeting into one stable JSON response.

Why it exists: This is the actual, callable surface every Context-Pack-aware Skill (see Multi-Agent Skill Integration) uses — see it fully documented, flags and all, in the Command Reference.

Example — a deliberately tight budget, showing mandatory content always wins:

misterspec internal context SPEC-017 --intent planning --budget 300
{"ok":true,"context":{"budget":300,"budget_exceeded":true,"overage":7,
"items":[/* Constitution + target only — everything else trimmed */],
"diagnostics":{"reduction_percent":80.0}}}
